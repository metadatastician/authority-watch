== Executive Summary

Authority Watch is a *work in progress* with a functional manual core but
*no production-ready automation*. The system enforces strict safety invariants
at the code level, but the operational infrastructure (API adapters, signing,
persistence) is not yet implemented.

*What is complete:*

* Core ontology (authority grades, review states, freshness, temporal facts)
* Zig executable with three commands (status, freshness, ingest)
* Safety invariants (canAdvance, canActivate) with unit tests
* UK insolvency profile configuration (7 sources defined)
* RSR compliance scaffolding

*What is NOT complete:*

* Automated source monitoring (all sources disabled)
* API adapters for official sources (legislation.gov.uk, GOV.UK, etc.)
* Production signing infrastructure
* Persistent observation storage
* Professional review workflow
* Consumer integration (sim-insolvency)

== Safety Status

=== Review State Transitions

*Truth claim:* It is *impossible* to skip a review state transition.

*Evidence:* The `canAdvance()` function in `zig/src/core.zig` uses a
switch expression that returns `false` for any unlisted transition.
The unit test `test "review states cannot be skipped"` verifies that
`.observed` cannot advance to `.parsed` (skipping `.retrieved` and
`.source_verified`).

*Gap:* No integration test that verifies the entire pipeline end-to-end.

=== Bundle Activation

*Truth claim:* It is *impossible* to activate a bundle without satisfying
all 8 gates.

*Evidence:* The `canActivate()` function in `zig/src/core.zig` uses a
conjunction (AND) of all 8 conditions. The unit tests verify that:

* unsigned bundles cannot activate
* revoked bundles cannot activate

*Gap:* No test for the full combination of all 8 gates simultaneously.

=== Data Integrity

*Truth claim:* SHA-256 digests correctly detect any byte change.

*Evidence:* The unit test `test "raw digest changes on any byte change"`
verifies that "official source" and "official source." produce different
digests.

*Gap:* No test for large files or edge cases (empty files, etc.).

== Blockers to Production Use

The following must be addressed before Authority Watch can be used in
production:

. [ ] Implement persistent observation storage (append-only ledger)
. [ ] Implement at least one source adapter (legislation.gov.uk or GOV.UK)
. [ ] Complete licence review for all enabled sources
. [ ] Implement signing infrastructure with trusted keys
. [ ] Implement professional review workflow with audit trail
. [ ] Implement consumer integration (sim-insolvency)
. [ ] Configure CI/CD pipeline with quality gates
. [ ] Complete security review of all components

== What Is Safe to Use NOW

The following are safe for experimentation and development:

* Manual ingestion of test files (`just ingest`)
* Review of the domain model (Idris2, AffineScript)
* Extension of the core types (Zig, Idris2)
* Addition of new profiles (configuration only)
* Development of source adapters (without enabling them)

The following are NOT safe:

* Enabling any source without licence review
* Bypassing canAdvance() or canActivate() checks
* Using Authority Watch for production legal determinations
* Publishing any bundle as authoritative
