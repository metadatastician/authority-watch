= Roadmap — Authority Watch
:toc:
:icons: font

[.lead]
This document outlines the planned milestones for Authority Watch, including
the work required, success criteria, and dependencies for each milestone.

== Overview

Authority Watch is being developed in 6 sequential milestones, each building
on the previous. The current focus is completing Milestone 1 (manual
precision core) and beginning Milestone 2 (official APIs).

[cols="1,1,1,2"]
|===
| Milestone | Status | Priority | ETA

| Milestone 1: Manual Precision Core | 70% Complete | High | 2026-08-XX
| Milestone 2: Official APIs | 0% Complete | High | 2026-09-XX
| Milestone 3: Professional Material | 0% Complete | Medium | 2026-10-XX
| Milestone 4: Consumer Integration | 0% Complete | Medium | 2026-11-XX
| Milestone 5: NNTPS Review Mirror | 0% Complete | Low | 2026-12-XX
| Milestone 6: Hosted Service | 0% Complete | Low | 2027-Q1
|===

== Milestone 1: Manual Precision Core

*Status:* 70% Complete (Core functionality implemented, RSR compliance added)

*Goal:* Establish the foundation for all subsequent milestones with a
strictly-controlled, manual-only precision core.

=== Work Items

[cols="1,1,1,2"]
|=== 
| ID | Status | Priority | Description

| M1-001 | Complete | High | Core ontology (AuthorityGrade, ReviewState, Freshness, TemporalFacts)
| M1-002 | Complete | High | Zig executable with status, freshness, ingest commands
| M1-003 | Complete | High | Safety invariants (canAdvance, canActivate) with unit tests
| M1-004 | Complete | High | UK insolvency profile with 7 sources
| M1-005 | Complete | High | RSR compliance scaffolding (.machine_readable/)
| M1-006 | In Progress | High | Comprehensive documentation (README, EXPLAINME, AFFIRMATION, AUDIT, GOVERNANCE)
| M1-007 | Not Started | Medium | Persistent observation storage (append-only ledger)
| M1-008 | Not Started | Medium | Formal proof of review state properties (Idris2)
|=== 

=== Success Criteria

* [x] Core types are defined and tested
* [x] CLI commands work correctly
* [x] Safety invariants prevent state bypass
* [x] Unit tests cover all core functions
* [x] Profile configuration is complete
* [x] RSR compliance files are in place
* [ ] Documentation is complete and accurate
* [ ] Persistent storage is implemented
* [ ] Formal proofs are complete

=== Dependencies

* None (this is the foundation milestone)

=== Work Items

|=== 
| ID | Status | Priority | Description

| M2-001 | Not Started | High | legislation.gov.uk API adapter with rate limiting
| M2-002 | Not Started | High | GOV.UK Content API adapter
| M2-003 | Not Started | High | Licence review and documentation for both sources
| M2-004 | Not Started | Medium | UK Parliament API adapter
| M2-005 | Not Started | Medium | Source health monitoring and reporting
| M2-006 | Not Started | Medium | Error handling and retry logic
| M2-007 | Not Started | Medium | Fixture generation for testing
|=== 

=== Success Criteria

* [ ] legislation.gov.uk adapter is functional
* [ ] GOV.UK adapter is functional
* [ ] All licence terms are reviewed and documented

* [ ] Tests cover all adapters

=== Success Criteria

== Beyond Milestone 6

Future work after Milestone 6 may include:

* Additional jurisdictions beyond UK
* Additional domains beyond insolvency
* Web-based review interface
* Machine learning-assisted classification (with human oversight)
* Integration with other estate projects
