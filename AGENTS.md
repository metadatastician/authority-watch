# Authority Watch agent rules

- Preserve the distinction between observation, detected change, interpretation,
  approval, signing, publication, and consumption.
- Never generate, approve, or publish an authoritative legal rule without the
  explicitly recorded human review required by the active profile.
- Never commit production observations, private review material, signing keys,
  credentials, or source archives.
- Prefer official APIs and feeds. Do not bypass access controls or invent
  licence permission.
- AffineScript is the principal application contract; pure Zig owns host and
  acquisition boundaries; Idris2 owns invariants. Do not introduce Python,
  TypeScript, Node application logic, React, or C FFI.
- Mark unavailable estate integrations as capability-gated. Do not invent APIs
  for projects that were not located or do not yet implement the needed
  capability.
- All example authority data and rule changes are non-authoritative fixtures.
