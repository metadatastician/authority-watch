= Dependencies — Authority Watch
:toc:
:icons: font

[.lead]
This document records all dependencies of Authority Watch, their current
status, licence terms, and integration boundaries. It is the canonical
source for dependency information.

== IMPORTANT CLARIFICATIONS

[IMPORTANT]
====
*FFI IS PURE ZIG:* There is NO C FFI in this project. The FFI layer uses pure Zig only.

*ABI IS PURE IDRIS2:* The ABI layer uses pure Idris2 only, with type-level formal definitions.

*ESTATE ADAPTER:* The correct estate ABI adapter is `zig-unified-hexadeca-adapter`
  (in hyperpolymath estate). This is NOT the same as `unified-hexadeca-api`.

*NOT IN rsr-template-repo:* Neither `zig-unified-hexadeca-adapter` nor
  `unified-hexadeca-api` are in rsr-template-repo. They are in the hyperpolymath
  standards repo or other hyperpolymath estate repos.
====

== Dependency Summary

Authority Watch has four classes of dependencies:

* *Runtime*: Required to build and run the application
* *Development*: Required for development and testing
* *Inspected*: Reviewed but not currently integrated
* *Blocked*: Explicitly blocked pending resolution

== Dependency Review Process

Before integrating any new dependency:

. *Identify the licence*: Determine the exact licence of the dependency
. *Check compatibility*: Verify it is compatible with PMPL-2.0-or-later
. *Review terms*: Check for any special terms or restrictions
. *Document*: Add to this file with all relevant information
. *Approve*: Obtain approval from maintainers

== Dependency Management

=== Version Pinning

* Zig: Version is determined by the build system (zig build)
* Idris2: Version is determined by the idris2 command
* just: Version is not pinned (system dependency)

=== Updating Dependencies

To update a dependency:

. Identify the new version
. Verify licence compatibility (if licence changed)
. Test the update locally
. Update this document with the new version
. Submit a PR with the change

== Security Considerations

* All dependencies are reviewed for known vulnerabilities
* No dependency has known critical vulnerabilities at this time
* Security updates are prioritized over feature updates
* Dependencies with security issues are blocked or updated immediately
